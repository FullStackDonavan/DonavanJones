## Who This Is For

You have tools: an API, an admin panel, a homelab, an internal system. You want people to drive them in plain English ("restart whisper on the voice box", "is Charlie ok", "load granite on Nova") without sending every request to a hosted model, and without a 7B model eating the memory your real workloads need.

This blueprint is the complete path from "a small model that gets tool calls right a third of the time" to "a small model that gets them right 98% of the time on wording it has never seen", on hardware you own. It's the working code behind the post [From 34% to 98%: Teaching a 0.6B Model to Run My Homelab](/blog/ai-engineering/25-tiny-tool-calling-model-34-to-98).

## Why It's Different From Just Reading the Post

The post tells the story and the lessons. The blueprint is the part you'd otherwise rebuild over a week of evenings: the six dataset generators, the scoring harness that keeps you honest, the serving code that makes a Qwen3 LoRA behave the same in production as it did in training, and the command bar that turns a model's guess into a confirmed action.

Every file is copied from the system the post describes, with addresses and tokens removed. Nothing was written after the fact for the download.

## The Results It Reproduces

From v3 on, all scores are on the same 103 held-out questions: phrasings the model never trained on, with names it has to resolve. v1 and v2 were scored on earlier test splits.

| Model | Dataset | Score |
|---|---|---|
| Qwen3 0.6B, no training | — | 34% |
| FunctionGemma 270M + LoRA | v1 | 21% |
| FunctionGemma 270M + LoRA | v2 (internal IDs) | 43% |
| FunctionGemma 270M + LoRA | v3 (the user's own words) | 77% |
| FunctionGemma 270M + LoRA | v4 (targeted fixes) | 80% |
| Qwen3 0.6B + LoRA | v4, through Ollama's template | 85% |
| Qwen3 0.6B + LoRA | v4, exact training prompt | 94% |
| **Qwen3 0.6B + LoRA** | **v5** | **98%** |

## The Workflow

1. **Define your functions.** Five to fifteen, each with plain-English argument descriptions ("the Jetson, as the user named it").
2. **Write the names layer.** Every thing your users can mention, with the ways they mention it. The model copies words; code turns words into IDs.
3. **Generate the dataset.** Templates per function, held-out templates for testing, near-miss pairs for functions that sound alike, a few off-topic questions answered in text.
4. **Train on the GPU box.** About 15–20 minutes on an RTX 3090 for 1,700 rows.
5. **Deploy and score.** Attach the adapter to the base model on the device that will serve it, then run base vs LoRA on the held-out questions.
6. **Read the misses, fix the data, repeat.** Every version in this kit exists because of a specific pattern in the previous version's misses.

## What It Won't Do

It won't make a 0.6B model reason. It makes it reliable at one job: picking the right function and copying the right words out of a short request. Anything that needs judgment stays with you. That's why every change goes through a confirmation step, and nothing destructive is a function at all.
